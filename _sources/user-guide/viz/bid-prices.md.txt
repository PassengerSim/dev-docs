# Bid Prices and Displacement

Bid prices help revenue management decide whether to accept a booking or keep capacity available for
later passengers. Here we can watch those prices change as departure approaches, starting with
carrier averages and then looking at individual legs and paths.

You can read about the underlying data and how to collect it in
[Bid Prices and Displacement](../summary-tables/bid-prices.md).

The setup below loads both demo results. We’ll use their actual carrier names and airport codes, so
you can run these examples without substituting your own data.

When you plot twelve or fewer legs or paths, colors help you tell them apart. With more lines, the
charts leave out those ID colors to avoid an oversized legend. You can still hover over a line to
see its ID, day, mean price, standard deviation, and observation count. Path tooltips also identify
the cabin, and comparison tooltips tell you which run the line belongs to. Missing statistics are
left missing rather than treated as zero.

## Set up the Europa examples

We’ll use `europa/upe` for the single-run charts and compare it with `europa`. The first load may
run the demo; later calls reuse its cached result.

```{code-cell} ipython3
import altair as alt
import passengersim as pax

# Keep all observations available when a figure contains more than 5,000 rows.
alt.data_transformers.disable_max_rows()
summary = pax.demo_result("europa/upe")
contrast = pax.demo_result({"europa": "europa", "europa/upe": "europa/upe"})
baseline = contrast["europa"]
alternative = contrast["europa/upe"]
```

## Collect the extra price histories

The standard demo archive does not contain path-price history or the callback observations used
later on this page. Here we replay the same demos, enabling those collectors. We keep the original
random seed, sample counts, and revenue-management settings. The extra results are cached in a
temporary-directory cache, separately from `demo_result`.

We’ll track Stroop flight 211 (KEF–AMS), whose UPE revenue-management system uses bid prices. The
matching nonstop path also has ID 211. The first run of this cell takes longer than loading the
standard demos; later runs reuse its saved results.

```{code-cell} ipython3
from pathlib import Path
import tempfile
from passengersim.contrast import Contrast
from passengersim.callbacks.bid_price_detail import collect_leg_bid_price_detail
from passengersim.tracers import bid_price as traced_bp


def collect_demo(name: str) -> pax.SimulationTables:
    """Replay a demo with the recording needed by this page."""
    cfg = pax.Config.from_yaml(pax.demo_network(name))
    cfg.outputs._write_no_files()
    cfg.outputs.reports = set()
    cfg.simulation_controls.show_progress_bar = False
    cfg.simulation_controls.collect_path_bid_prices = True
    cfg.db = None
    cache_dir = Path(tempfile.gettempdir()) / "passengersim-viz-guide" / "bid-prices-v1" / name
    simulation_class = pax.MultiSimulation if cfg.simulation_controls.num_trials > 1 else pax.Simulation
    with simulation_class(cfg) as sim:
        sim.daily_callback(collect_leg_bid_price_detail({211}))
        traced_bp.LegBidPriceTracer([211]).attach(sim)
        traced_bp.PathBidPriceTracer([211]).attach(sim)
        traced_bp.LegBidPriceArrayTracer([211]).attach(sim)
        traced_bp.LegBidPriceVectorTracer([211]).attach(sim)
        return sim.run(cache_dir=cache_dir)


recorded = Contrast({name: collect_demo(name) for name in ("europa", "europa/upe")})
recorded_summary = recorded["europa/upe"]
```

## Average bid prices by carrier

Start with this chart for a broad view of bid prices. Each carrier’s line averages across its legs,
so it is a useful overview before you investigate individual flights.

Use `by_carrier` to separate carriers or filter to one. `cap=None` includes all reporting prices,
`"some"` restricts to remaining-capacity observations, and `"zero"` selects sold-out observations.
`show_stdev=True` shows a two-standard-deviation band, or supply a multiplier. For comparison bands,
select one carrier. Single-run `trial` selects a trial instead of combining them.

For one run, call
[fig_bid_price_history](passengersim.summaries.SimulationTables.fig_bid_price_history):

```{code-cell} ipython3
summary.fig_bid_price_history(by_carrier="Tapas", show_stdev=True)
```

To compare runs, use [fig_bid_price_history](passengersim.contrast.fig_bid_price_history):

```{code-cell} ipython3
contrast.fig_bid_price_history(by_carrier="Tapas", show_stdev=True)
```

## Bid prices for individual legs

To see what is happening on particular flights, plot the native leg history. You get the daily mean
price and, by default, a second panel showing how much prices varied across the samples and trials
kept after burn-in.

PassengerSim collects this history by default, so you don’t need to attach a callback. Set
`std_dev=False` if you only want the mean-price panel.

You can choose legs with `ids`, or narrow the chart using `carrier`, `orig`, and `dest`. For
example, supplying both a carrier and an origin keeps only that carrier’s legs from that airport.
Each of those three filters accepts one name or a tuple of names. These filters use the `legs`
table, so keep that table with your results. When comparing runs, `include` lets you choose which
runs to show.

For one run, call [fig_leg_bid_prices](passengersim.summaries.SimulationTables.fig_leg_bid_prices):

```{code-cell} ipython3
summary.fig_leg_bid_prices(carrier="Tapas", std_dev=False)
```

To compare runs, use [fig_leg_bid_prices](passengersim.contrast.fig_leg_bid_prices):

```{code-cell} ipython3
contrast.fig_leg_bid_prices(carrier="Tapas", std_dev=False)
```

## Bid prices for passenger paths

This chart follows bid prices for each path and cabin. Separate lines keep the cabins distinct, and
the second panel shows how much the prices varied across the retained observations.

Turn on `simulation_controls.collect_path_bid_prices=True` before you run the simulation. You can
then use the same filters as for legs: `ids`, `carrier`, `orig`, and `dest`. The carrier and airport
filters use the `paths` table; the airports are the endpoints of the whole itinerary, including when
it connects.

By default, the chart shows the ordinary path price, based on its legs. Set `augmented=True` to
include the reference-class fare adjustment described in the
[bid-price table guide](../summary-tables/bid-prices.md). As with legs, `std_dev=False` hides the
variability panel, and `include` selects runs in a comparison.

For one run, call
[fig_path_bid_prices](passengersim.summaries.SimulationTables.fig_path_bid_prices):

```{code-cell} ipython3
recorded_summary.fig_path_bid_prices(ids=(211,), augmented=True)
```

To compare runs, use [fig_path_bid_prices](passengersim.contrast.fig_path_bid_prices):

```{code-cell} ipython3
recorded.fig_path_bid_prices(ids=(211,), augmented=True)
```

The baseline Europa demo does not use bid-price control, so its native path-price table has no
observations for this path. Although both results are included in the comparison, only the UPE line
appears here. The tracer path-price comparison later on this page records reporting prices in both
runs and can show both lines.

## Displacement costs

Displacement costs describe the opportunity cost of using capacity for a booking. This chart shows
the daily averages reported by the revenue-management system for each carrier.

Choose `by_carrier` and `show_stdev` as for carrier bid prices. Single-run `trial` selects a trial.
Comparison bands require selecting one carrier; comparison `width` and `height` control facet size.

For one run, call
[fig_displacement_history](passengersim.summaries.SimulationTables.fig_displacement_history):

```{code-cell} ipython3
summary.fig_displacement_history(by_carrier="Tapas", show_stdev=True)
```

To compare runs, use [fig_displacement_history](passengersim.contrast.fig_displacement_history):

```{code-cell} ipython3
contrast.fig_displacement_history(by_carrier="Tapas", show_stdev=True)
```

## Callback bid-price distributions

Sometimes an average and a standard deviation aren’t enough. You may want to see the median price,
or the range containing most of the observed prices. The callback figures below can show those
details if you collect daily observations before running. These plotting methods are always
available on summaries; they only need the observations recorded by the daily collector. Attach it
in Python as shown above, or enable it in a configuration:

```yaml
callbacks:
  leg_bid_price_detail:
    parameters:
      leg_ids: [211]
```

The collection cell above has already attached the daily callback for flight 211.

### `fig_leg_bid_price_detail_rake`

Show a selected leg's median, mean, and percentile trajectories through the booking horizon. Choose
`leg_id`; `color` and `mean_color` control the marks. `raw_df=True` returns the summarized
observations. There is no dedicated contrast method; plot each run separately.

```{code-cell} ipython3
recorded_summary.fig_leg_bid_price_detail_rake(leg_id=211)
```

API:
[`fig_leg_bid_price_detail_rake`](passengersim.callbacks.bid_price_detail.fig_leg_bid_price_detail_rake).

### `fig_leg_bid_price_history`

Plot one statistic across a carrier's legs. Specify `carrier` and `measure`: `"mean"`, `"q10"`,
`"q25"`, `"q50"`, `"q75"`, `"q90"`, or `"median"`. This callback method is not the native
`fig_leg_bid_prices` method. It also needs leg definitions for labels and haul grouping. Set
`haul_category_labels=None` to avoid distance-quantile facets, for example on small networks with
repeated leg distances. `opacity` controls overplotting; `max_rows` limits the displayed data. There
is no `raw_df` or dedicated contrast method.

```{code-cell} ipython3
recorded_summary.fig_leg_bid_price_history("Stroop", measure="median", haul_category_labels=None)
```

API:
[`fig_leg_bid_price_history`](passengersim.callbacks.bid_price_detail.fig_leg_bid_price_history).

## Tracer bid-price figures

The functions in `passengersim.tracers.bid_price` consume attached tracer data. Their names overlap
the native summary methods, so use a module alias to make the source explicit. See
[Tracers](../tracers.md) for lifecycle and collection details. Attach a fresh tracer before each
run; an existing result cannot reconstruct observations that were not collected.

The setup above attaches the leg and path tracers to both demo runs.

### Tracer `fig_leg_bid_prices` and `fig_path_bid_prices`

Plot tracer means and optionally standard deviations. Both accept `ids`, `std_dev`, and `raw_df`;
for a `Contrast`, `include` restricts sources. These functions do not have the native metadata
filters or the native path `augmented` option. Native and callback timing can produce different
values.

```{code-cell} ipython3
traced_bp.fig_leg_bid_prices(recorded_summary, ids=(211,))
```

```{code-cell} ipython3
traced_bp.fig_path_bid_prices(recorded_summary, ids=(211,))
```

```{code-cell} ipython3
traced_bp.fig_leg_bid_prices(recorded, include=("europa", "europa/upe"))
```

```{code-cell} ipython3
traced_bp.fig_path_bid_prices(recorded, include=("europa", "europa/upe"))
```

API: [`fig_leg_bid_prices`](passengersim.tracers.bid_price.fig_leg_bid_prices),
[`fig_path_bid_prices`](passengersim.tracers.bid_price.fig_path_bid_prices).

### `fig_leg_bid_price_array`

A heatmap of a selected leg's mean bid-price array across seats sold and days prior. Attach
`LegBidPriceArrayTracer([211])` before the run. It captures arrays at the beginning of samples, so
the plot does not represent within-sample price updates.

```{code-cell} ipython3
traced_bp.fig_leg_bid_price_array(recorded_summary, leg_id=211)
```

Use `raw_df=True` to inspect the plotted values. This is a single-summary function; call it
separately for each run to compare arrays.

API: [`fig_leg_bid_price_array`](passengersim.tracers.bid_price.fig_leg_bid_price_array).

### `fig_leg_bid_price_vectors`

A heatmap of the mean bid-price vectors for one leg. Attach `LegBidPriceVectorTracer` to collect the
vectors before generating the figure.

```{code-cell} ipython3
traced_bp.fig_leg_bid_price_vectors(recorded_summary, leg_id=211)
```

Use `raw_df=True` for the plotted data. This is a single-summary function, not a `Contrast` method.

API: [`fig_leg_bid_price_vectors`](passengersim.tracers.bid_price.fig_leg_bid_price_vectors).
