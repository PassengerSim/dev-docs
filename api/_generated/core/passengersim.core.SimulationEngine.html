    add_booking_event(event_time, num_pax)¶

    Add a booking event for a demand to the simulation’s event queue.

    When the event is reached, go() processes it internally as a booking request for num_pax passengers from demand; it is not returned to the caller. The queued event shares the underlying demand object.

    Parameters:
    demand : Demand

    The demand making the booking request.

    event_time : float¶

    Timestamp for the event, in Unix time.

    num_pax : int¶

    Number of passengers in the booking request, between 1 and 32767.

    Raises:

    • TypeError – If demand is not a Demand, or num_pax is not an int.

    • ValueError – If num_pax is out of range, or demand is not initialized.

    build_connections()¶

    Build connections for the demands

    Notes

    For minimum and maximum connection times, a flight is domestic when its endpoint airports share a country or a nonempty domestic_group. Country codes are unchanged, and same-country flights remain domestic regardless of group membership. With Schengen groups populated from a PassengerSim config, MAD-FRA-HEL uses DD thresholds, MAD-FRA-JFK uses DI, and JFK-FRA-HEL uses ID.

    See passengersim.connection_builder.prebuild_connections() for automatic Schengen membership, place overrides, and rebuilding paths after changes. When configuring an engine directly, set airport domestic_group values explicitly; use existing_paths="replace" to rebuild existing paths.

    choice_set_sampling_probability¶

    Choice set data is captured using this probability. i.e. 0.1 will capture 10% of the data. This is usually calculated by the driver program, and not usually set by an end user. Larger networks with lots of samples could result in many millions of choice sets and will rapidly run you out of memory and/or file space if you’re not careful

    fare_segment_counters()¶

    Get current-sample sales and revenue by segment for many fares at once.

    This is a bulk accessor intended for tracers and callbacks that need to read segment-level counters for a large number of fares at every DCP; it avoids a Python-level loop with one call per fare and segment.

    Parameters:
    fares : Sequence[Fare]

    The fares to read.

    segments : Sequence[str]

    The demand segment names to read. A segment with no sales on a fare in the current sample reports zero sales and zero revenue.

    Returns:

    numpy.ndarray – A float64 array of shape (len(fares), len(segments), 2). The last axis holds (sold, revenue), both accumulated since the start of the current sample (i.e. cumulative within the sample, reset at the next sample). Revenue is the realized revenue, which is exact under continuous pricing.

    Raises:

    TypeError – If any element of fares is not a Fare, or any element of segments is not a string.

    record_daily_statistics()¶

    Record carrier daily statistics and optional leg and path bid-price statistics.

    Parameters:
    days_prior : int

    Current integer day before departure. Native leg collection requires a day between zero and the largest configured DCP, inclusive.

    Returns:

    int – Zero during burn-in, otherwise one. When enabled, native leg collection records only the first observation per iteration/trial/sample/day, using the leg-level reporting price, including for sold-out legs. Multi-cabin legs use their leg price without cabin capacity sharing. Optional path collection records paired total and effective reference-class thresholds per cabin for bid-price-controlled carriers. Both prices share one count; the reference is the lowest-decision-price class with a finite positive adjusted fare. Zero is allowed for bp_loose only when the total bid price is zero within 1e-9.

    Raises:

    RuntimeError – Native leg collection is enabled and the day is outside the DCP horizon, or the collection horizon changed after accumulator allocation.
